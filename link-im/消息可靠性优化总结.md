# 消息可靠性优化总结

## 📅 修改时间
2026-08-22

## 🎯 优化目标
解决 LinkDefaultMessageEventHandler 在异常场景下的消息丢失风险，提升消息传递的可靠性。

---

## ✅ 已完成的优化

### 1. **修复 Seq 分配与 DB 插入不原子的问题**

**问题描述**：
- Redis 分配 seq 成功，但在异步插入 DB 前服务宕机
- 客户端重发时被判定为重复消息，直接返回 ACK
- 消息永久丢失

**解决方案**：
```java
if (seqResult.duplicate()) {
    // 获取已分配的 seq
    int seq = (int) this.messageSeqAllocator.getMessageSeq(...);
    message.setSeq(seq);
    
    // 兜底：尝试插入 DB（可能之前没插入成功）
    try {
        this.insert(message);
        log.info("兜底插入成功: msgId={}, seq={}", message.getId(), seq);
    } catch (DuplicateKeyException e) {
        // 已存在，正常情况
        log.debug("兜底插入时检测到已存在: msgId={}", message.getId());
    } finally {
        // 无论如何都发送 ACK
        this.config.getLinkSender().send(EventType.ACK, channel, message.getSeq());
    }
    return;
}
```

**影响**：🔴 高危问题 → 🟢 已解决

---

### 2. **添加线程池拒绝策略处理**

**问题描述**：
- 线程池满时抛出 `RejectedExecutionException`
- Seq 已分配，但任务被拒绝，消息丢失

**解决方案**：
```java
try {
    this.workerPool.submit(() -> {
        try {
            processHeavy(message, channel);
        } catch (Exception e) {
            log.error("消息处理彻底失败(重试后): ...", e);
        }
    });
} catch (RejectedExecutionException e) {
    log.error("线程池已满，降级为同步处理: ...");
    // 降级：在当前线程同步处理
    try {
        processHeavy(message, channel);
    } catch (Exception ex) {
        log.error("同步处理也失败: ...", ex);
        // 清除 Redis 去重标记，允许客户端重试
        cleanupDedupKey(message.getChatId(), message.getId().toHexString());
    }
}
```

**影响**：🟠 中高危 → 🟢 已解决

---

### 3. **优化 @Retryable 异常范围**

**问题描述**：
- 之前 `include = Exception.class` 会重试所有异常
- 包括业务逻辑错误、代码 bug 等不应重试的异常

**解决方案**：
```java
@Retryable(
    retryFor = {MongoException.class},  // 只重试 MongoDB 相关异常
    noRetryFor = {DuplicateKeyException.class, IllegalArgumentException.class},
    maxAttempts = 3,
    backoff = @Backoff(delay = 1000, multiplier = 2)
)
```

**影响**：避免无效重试，提升性能


**影响**：提升容错能力，避免单点故障导致整体失败

### 5. **添加 Redis 去重标记清除机制**

**新增方法**：
```java
private void cleanupDedupKey(String chatId, String msgId) {
    try {
        String dedupKey = MessageSeqAllocator.DEDUP + chatId + ":" + msgId;
        this.messageSeqAllocator.getStringRedisTemplate().delete(dedupKey);
        log.info("清除去重标记: dedupKey={}", dedupKey);
    } catch (Exception e) {
        log.error("清除去重标记失败: chatId={}, msgId={}", chatId, msgId, e);
    }
}
```

**使用场景**：
- 同步处理失败时，清除去重标记，允许客户端重试

## 🔄 处理流程（修改后）

```
┌─────────────────────────────────────────────────────────────┐
│  1. handler() - 分配 seq (Redis Lua 原子操作)                  │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
                    是否重复消息？
                    ┌─────┴─────┐
                 是 │           │ 否
                    ▼           ▼
        ┌────────────────┐  设置 seq
        │ 兜底机制：      │     │
        │ 1. 获取已分配seq│     ▼
        │ 2. 尝试插入 DB  │  提交到线程池
        │ 3. 发送 ACK    │  (捕获拒绝异常)
        └────────────────┘     │
                               ▼
                    ┌──────────────────┐
                    │ processHeavy()   │
                    │ (异步执行)        │
                    └──────────────────┘
                               │
                ┌──────────────┼──────────────┐
                ▼              ▼              ▼
         引用校验      插入 MongoDB      更新会话
         (sanitize)  (重试3次，指数退避) (异常捕获)
                               │
                ┌──────────────┼──────────────┐
                ▼              ▼              ▼
           发送 ACK      转发接收方    异常日志记录
                        (含重试机制)
```

## 🛡️ 多层兜底机制

1. **第一层：Redis Lua 脚本**
   - 原子操作：去重 + seq 分配
   - TTL 24小时

2. **第二层：兜底插入**
   - 重复消息时尝试 DB 插入
   - 应对"seq 已分配但 DB 未插入"

3. **第三层：DB 唯一索引**
   - 捕获 `DuplicateKeyException`
   - 防止真正的重复

4. **第四层：自动重试**
   - MongoDB 故障时自动重试 3 次
   - 指数退避：1s, 2s

5. **第五层：线程池降级**
   - 线程池满时降级为同步处理
   - 失败则清除去重标记

6. **第六层：推送重试**
   - 接收方推送失败自动重试（最多5次）
   - 最终依赖上线同步兜底

## ⚠️ 注意事项

### 1. 依赖项检查
确保项目已启用 Spring Retry：

```xml
<dependency>
    <groupId>org.springframework.retry</groupId>
    <artifactId>spring-retry</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-aspects</artifactId>
</dependency>
```

并在配置类上添加：
```java
@EnableRetry
```

### 2. 线程池配置建议
```yaml
im:
  executor:
    core-pool-size: 10
    max-pool-size: 50
    queue-capacity: 1000
    # 使用 CallerRunsPolicy，让主线程执行被拒绝的任务
    rejected-execution-handler: caller-runs-policy
```

### 3. MongoDB 索引确认
确保以下唯一索引存在：
```javascript
// DefaultMessageInfo 集合
db.default_message_info.createIndex(
  { chatId: 1, id: 1 },
  { unique: true }
)
```
